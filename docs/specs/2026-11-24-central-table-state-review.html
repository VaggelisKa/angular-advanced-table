Central table state: API before and after

The surface is the initiator and NatTableService is the single state manager. Renderers no longer keep their own copy of the state. This page shows what that means for code that uses the library.

base: tanstack-table-v9-migration minor · Breaking uncommitted

Who is affected

Most apps only use <nat-table-surface> and companion controls. That code does not change. The breaking part only reaches code that injects NatTableService and configures or reads it directly, usually a host that provides the service without a surface.

Surface usage

Unchanged
before = afterorders-page.html
<nat-table-surface
  [initialState]="{ pagination: { pageIndex: 0, pageSize: 25 } }"
  [enableSorting]="true"
  [(state)]="tableState"
  (sortingChange)="reload($event)">
  <nat-table-pagination [pageSizeOptions]="[25, 50, 100]" />
  <nat-table [data]="rows()" [columns]="columns" accessibleName="Orders" />
</nat-table-surface>

Inputs, slice outputs and the [(state)] two-way binding behave exactly as before. Internally the surface now hands all inputs to the service in a single configure() call.

Consumer-owned search control

Unchanged
before = aftertable-search.ts
private readonly tableService = inject(NatTableService);
protected readonly controller = computed(() => this.tableService.controller());

constructor() {
  this.tableService.registerSearch();
  inject(DestroyRef).onDestroy(() => this.tableService.unregisterSearch());
}

protected onInput(value: string): void {
  this.controller()?.patchState({ globalFilter: value, pagination: firstPage });
}

The controller contract (NatTableUiController.patchState), controller(), and the register* methods are untouched, so companion controls and custom controls keep working.

Host-provided service, without a surface

These are the changes reviewers should look at. Each example is a host component with providers: [NatTableService].

Configure surface settings

Breaking
beforedetached-positions.ts
private readonly service = inject(NatTableService);

constructor() {
  // config was written through patchState()…
  this.service.patchState({ enableSorting: true });
  // …or by setting the signals directly
  this.service.stickyHeader.set(false);
  this.service.locale.set('da');
}
afterdetached-positions.ts
private readonly service = inject(NatTableService);

constructor() {
  // one write path; the signals are read-only
  this.service.configure({
    enableSorting: true,
    stickyHeader: false,
    locale: 'da'
  });
}

patchState on the service meant "configuration" while patchState on a controller meant "view state". The service method is now configure(), so the name no longer clashes. Keys you leave out keep their value, as before.

Seed the initial state

Breaking
before
this.service.surfaceInitialState.set({
  sorting: [{ id: 'symbol', desc: false }]
});
this.service.surfaceMode.set('manual');
after
this.service.configure({
  initialState: { sorting: [{ id: 'symbol', desc: false }] },
  mode: 'manual'
});

Read the current state

Breaking
before
// service.state() held only the controlled slices,
// usually {} for a host without a binding
const bound = this.service.state();          // Partial<…>

// the real values lived inside the renderer
const sorting = this.service.controller()
  ?.table.atoms.sorting.get() ?? [];
after
// the resolved state for every slice
const sorting = this.service.state().sorting; // NatTableUserState

// only the [(state)] slices, if you need them
const bound = this.service.controlledState();

state now returns the controlled slices layered over the state the service owns, so it is complete even when no renderer is mounted yet. globalFilter keeps the consumer's value whether or not a search control is registered, matching what the surface emits.

Follow state changes

Breaking
before
effect(() => {
  const next = this.service.stateChangeEvent();
  if (next) this.persist(next);
});
after
effect(() => {
  const next = this.service.stateChanges();
  if (next) this.persist(next);
});

Same payload: the full committed state, including proposed values for controlled slices. Only the name changed.

Write view state

Breaking
before
// wrote the *controlled* partial: every slice you
// touched became controlled from then on
this.service.setState({ globalFilter: 'acme' });
this.service.updateState((s) => ({ ...s, pagination }));

// meant for renderers, but public
this.service.notifyStateChange(fullState);
after
// a user action: goes through the renderer, which
// normalizes it and commits it to the service
this.service.controller()?.patchState({ globalFilter: 'acme' });

// taking control of a slice, like [(state)] does
this.service.configure({ state: { globalFilter: 'acme' } });

setState, updateState and notifyStateChange are removed. The new seedState() and commitState() are the renderer side of the service; apps should not need to call them.

Swap renderers

Behaviour fix
beforeuser sorted by status, then swapped
@Component({

// from initialState: sorting jumps back to name ↑,
// page index, filters and selection reset too
aftersame template
@Component({
  providers: [NatTableService],
  template: `
    @if (wide()) {
      <nat-table [data]="rows" [columns]="columns" />
    } @else {
      <nat-list [data]="rows" [columns]="columns" />

Under <nat-table-surface> a swap already kept state, because the surface wrote every change back into its own state model. Locked by the new src/table/table-renderer-swap.spec.ts.

The same change, seen from the renderer engine (NatTableState). This is the bulk of the diff.

Merged state in the renderer engine

Internal
beforetable.state.ts
private readonly internalSorting = signal(DEFAULT.sorting);
private readonly internalGlobalFilter = signal('');
// …7 more internal* signals

mergedState = computed(() => ({
  sorting: normalize(this.state().sorting ?? this.internalSorting()),
  columnFilters: this.state().columnFilters ?? this.internalColumnFilters(),
  pagination: this.state().pagination ?? this.internalPagination(),
  // …
}));

updateState(updaters) {
  const next = resolve(this.mergedState(), updaters);
  this.commitInternalState(next); // 9 if-blocks
  this.flushTableOptions();
  this.natTableService.notifyStateChange(next);
}
aftertable.state.ts
private readonly userState = this.natTableService.state;



mergedState = computed(() => {
  const state = this.userState();
  return {
    sorting: normalize(state.sorting),
    columnFilters: state.columnFilters,
    pagination: state.pagination,
    // …
  };
});

updateState(updaters) {
  const next = resolve(this.mergedState(), updaters);
  this.natTableService.commitState(next);
  this.flushTableOptions();
}

The 20 computed(() => this.natTableService.x()) wrappers are also gone; the engine references the service signals directly. Pinning, order and sizing keep their equality guards, so TanStack row memoization is unaffected.

NatTableService member map

Every public member that changed. Members not listed (controller, setController, clearController, register*, has*, manual*, keybindings, keyboard) are unchanged.

patchState(config) configure(config) Same "omitted keys keep their value" rule
enableSorting.set(…) and the other config signals configure({ enableSorting }) Signals are now read-only
state() (controlled partial) controlledState()
none state() (resolved full state) New meaning for the old name
surfaceInitialState initialState Read-only
surfaceMode mode Read-only
stateChangeEvent stateChanges Same payload
setState, updateState removed Use the controller's patchState or configure({ state })
