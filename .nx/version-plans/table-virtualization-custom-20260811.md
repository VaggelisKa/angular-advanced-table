---
ng-advanced-table: minor
---

Add opt-in fixed-height row virtualization for `NatTable` through the `NatTableVirtualize` directive and `NatTableVirtualizationOptions`, shipped as a new `ng-advanced-table/virtualization` secondary entry point driven by a library-owned windowing engine with no virtual-scroll dependency.

The engine keeps one native table and scroll region, preserves the final sorted/filtered/paginated row model, renders accessibility-hidden native spacer rows instead of transform offsets (so sticky headers and pinned columns stay untouched), exposes absolute ARIA row positions, and bridges keyboard focus across unmounted ranges (Arrow, Page, and Control/Command + Home/End navigation). Windowing mounts the visible rows plus a configurable `overscan` (default `5`) on each side with half-overscan remount hysteresis, scroll events are observed passively outside the Angular zone and coalesced to animation frames, and window resize and orientation changes re-measure through the engine's own coalesced viewport listener. Malformed strategy geometry is normalized — invalid or duplicate logical indices and non-monotonic row extents are discarded before they can corrupt spacer geometry — unbounded regions are revalidated after async data and resizes, and arbitrary stable row IDs are compared structurally, so no ID content can erase a sequence boundary.

Appending rows does not reset the vertical window. The row-model reset compares the row-id sequence position by position and treats an unchanged prefix as an append, so cursor and "load more" fetching keeps the reader's scroll position and mounted window; sorting, filtering, paging, reordering, truncation, and replaced data still reset. Replacing the data with identical row ids likewise keeps the scroll position. Accessible focus is preserved across body-state and row-model changes, focus recovery is isolated per table, grid-start and visual Page navigation land on the right cell, and the grid's roving-tabstop row stays mounted while focus visits other cells inside the table.

`NatTableVirtualize` exposes a `(virtualRangeChange)` output emitting `{ startIndex, endIndex, count }` for the mounted window (inclusive bounds in the current row model, batched by the engine's overscan hysteresis) so applications can fetch on approach; appended data that leaves the window where it was emits nothing, so a fetch-on-approach handler is not re-entered by its own result. `NatTableVirtualRangeChange` is exported from `ng-advanced-table/virtualization`.

Nesting is isolated in both directions. Row-render strategies resolve with `{ self: true }`, so a nested `<nat-table>` or `<nat-list>` inside a virtualized table cannot inherit the outer table's row window and render a partial row set. Keyboard events, retained-row tracking, and focus recovery are scoped to the renderer that owns the focused cell: navigation inside a nested grid cannot move the outer window or recover focus into a same-index nested row, and a virtualized table rendered inside another table's row does not read that outer row's index for a keydown on its own header cell, so Page Up, Page Down, and arrow keys stay with the header row instead of paging the nested body.

Virtualization composes with sticky headers, pinned columns, column sizing, reordering, selection, pagination, state rows, and row activation. The engine is confined to the new entry point, so applications that never import `ng-advanced-table/virtualization` ship none of it — enforced at the artifact level by the package size budget's forbidden-import graph. The `ng-advanced-table` size ceiling stays at its existing 70,000 gzipped bytes — no raise.

Core gains only the engine-neutral half of the contract, published from the `common` and `domain-logic` barrels so its hand-written `src/index.ts` is untouched by virtualization: `NatTableRowRenderStrategy`, `NatTableVirtualItem`, and `NatTableRowRenderStrategyRegistry`, together with `NAT_TABLE_ROW_WINDOW_HOST`/`NatTableRowWindowHost` — a narrow view of table state that lets an opt-in renderer drive row windows without core exporting `NatTableState`. The row-render strategy registry is an optional `NatTableState` dependency, provided only by `NatTable`; renderer shells that never virtualize, such as `NatList`, provide nothing and stay free of any virtualization import.

Because virtualized bodies mount only a window of rows, `aria-rowcount` and body `aria-rowindex` are derived from the logical row model instead of the DOM. Row-render metrics keep working under virtualization with corrected cycle semantics: a render cycle is one row-model rebuild, and a moved row window restamps the timing clock without opening a new cycle, so rows that stay mounted across a scroll no longer re-report while rows that mount during a scroll report their real mount cost.

Sub-header rows are supported on the same fixed-height grid: the windowing math runs on composite slots (data row `i` sits at slot `i + subHeaderRowOffsets[i]`), a group-opening row and its sub-header mount and scroll as one block, and development builds warn when a rendered sub-header row diverges from the configured `rowHeight`. Table sub-header cells now render the shared row separator (the `--nat-table-cell-border-width`/`--nat-table-cell-border-color` tokens) so grouped rows match the rest of the table; their background stays on the existing `--nat-table-sub-header-background` token, defaulting to transparent. The `--nat-table-space-sub-header` padding moved from the cell onto the sticky group label, so the label keeps its inset instead of shifting while it clamps to the visible left edge during horizontal scrolling.

Pinned-cell stacking is corrected alongside it: horizontally scrolled content stays below pinned body and header cells when an unpinned cell has keyboard focus, translucent pinned-row focus and hover colors composite over the opaque pinned surface, and center and pinned row hover surfaces stay visually synchronized as the pointer moves between rows. The stacking contract is documented and covered for both full-row and custom-virtualized rendering in real browsers.

This first strategy virtualizes only the rows already supplied to the table. The feature is documented — including the low-level custom-adapter responsibility boundary — with a 10,000-row showcase example that groups its rows by region, and is locked with rendered and browser regressions.
