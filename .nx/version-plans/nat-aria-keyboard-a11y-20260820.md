Keyboard accessibility overhaul across the table header, toolbar items, pagination, and pinned zones.

**Header controls are managed cell controls.** Header `<th>` elements were the only grid cells missing `natTableCell`, so every sort and column-menu button was a natural tab stop (~22 stray stops on a table with 11 sortable columns and 14 menus). Both header rows now carry `natTableCell`, converging header keyboard interaction on the body-cell contract: sort and menu buttons are managed (`tabindex="-1"` plus `data-nat-table-managed-cell-widget`), arrow keys move between header cells, Enter steps into a cell's first control, Tab / Shift+Tab cycle within the cell, Escape returns to the cell, and a sorting-only header still delegates focus straight to its sort button so a single Enter sorts. `NatTable.onHeaderKeydown` ignores already-consumed events, so a key handled by the cell-interaction model can never also trigger resize or reorder. This changes behavior for keyboard users who relied on Tab reaching header controls directly; the ARIA grid arrow-key + Enter model is now the single path.

**The header column menu is fully keyboard-operable end to end.** The `ngGridCellWidget` wrapper is removed from `NatTableHeaderActions` — the cell never registers it (`GridCell`'s content query cannot see into the flexRender-created view), yet it self-assigned `tabindex="0"` while its cell was active, a phantom focus stop that swallowed Tab. Menu item activation moved from per-item `(click)` handlers to the menu's `itemSelected` output with stable values (`pin:left`, `move:right`, …), because `@angular/aria` menus activate items by emitting `itemSelected` and never fire a DOM click — the `(click)`-only wiring made every menu action keyboard-dead. Controls inside a menu attached within a cell are excluded from cell-control management (the menu owns its items' roving tabindex). Keyboard-opening the menu reliably focuses its first item (the trigger re-issues its open once the overlay's deferred items have rendered), and after pinning or moving a column focus returns to that column's menu trigger instead of dropping to `<body>` when the `<th>` is re-inserted.

**Header backward-focus loop fixed.** `handleCellInteractionFocusIn`'s single-control delegation fired on every `focusin`, including the one raised while focus travelled backwards out of the cell, so Shift+Tab ping-ponged forever between a sorting-only header cell and its sort button. Delegation now only fires when focus arrives from outside the cell.

**`natToolbarItemFocusTarget` for wrapped toolbar controls.** A CSS selector nominating the descendant that should receive focus when a toolbar item is a wrapper (Angular component host, Stencil custom element, design-system button) rather than the control itself. The selector searches an open shadow root before light DOM, suppression is re-applied through a `MutationObserver` when the wrapper re-renders, a not-yet-upgraded custom element is retried on `customElements.whenDefined`, and a closed shadow root warns in dev mode. Suppression is reversible: when the selector is repointed, cleared, or stops resolving, the former control gets back the `tabindex` it carried before. Registration and hit-testing stay on the host so Aria event routing keeps working.

**`NatTablePagination` is a plain control row, not a toolbar.** It renders the page-size select and pager as two labelled `role="group"` blocks; all three controls are ordinary tab stops (the toolbar's roving tabindex previously collapsed them into one, leaving Previous/Next reachable only by unadvertised arrow keys), nesting `role="toolbar"` inside a consumer toolbar is gone, and `[disabled]` on the pager buttons is the native property so a disabled Previous is skipped by Tab.

**Pinned zones stay above and opaque under focused/hovered content.** Focused non-pinned cells no longer rise above the sticky header or pinned zones (only pinned cells take `--nat-table-z-index-focus-cell`), and the hovered/focused row tints on pinned cells render as a layer above the opaque pinned background instead of replacing it, so scrolled center content can no longer bleed through pinned cells.
