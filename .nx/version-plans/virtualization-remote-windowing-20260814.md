Add remote windowing to `NatTableVirtualize`: two new directive inputs, `remoteRowCount` and `rowWindowOffset` (default `0`), decouple the scroll extent from the rows the table holds. The scrollbar, `aria-rowcount`, and the `(virtualRangeChange)` indexes span the declared remote total; the consumer supplies one contiguous loaded window plus its start index, and every logical index outside that window renders as a fixed-height placeholder row. Omitting `remoteRowCount` leaves every existing virtualization behavior unchanged.

The built-in English `tableSummary` and `listSummary` copy changes for every table whose shown rows are fewer than the represented total: the "Showing X of Y rows" subset phrasing now fires whenever the counts differ, not only for filtered views, so an unfiltered remote window — or an unfiltered paginated page — can never describe itself with a row count that contradicts its own `aria-rowcount`. Views that show every represented row keep the previous plain phrasing.

The remote extent reaches core through the existing engine-neutral `NatTableRowRenderStrategy` seam, which gains two optional fields: `logicalRowCount` (a `Signal<number | null>`, `null` meaning the loaded row model is the full extent) and `rowWindowOffset`. Core never imports the virtualization entry point; it clamps unusable values so the loaded window always fits inside the extent, maps mounted logical indexes onto loaded rows in `buildNatTableBodyRenderPlan`, and renders the rest as placeholder slots through a new discriminated body-plan row union. `NatTableState.stateTotalRowCount` and the summary/announcement totals report the remote total while it is active, `bodyState` stays on the rows branch for a non-empty remote extent even when the loaded window is momentarily empty, and the TanStack table `meta` gains `natTableRemoteRowCount` so companion controls can detect a windowed row model.

Placeholder rows are real grid rows: absolute `aria-rowindex`, `aria-busy="true"`, one structurally correct fixed-height cell per visible column, and screen-reader copy from the new core-domain `accessibility.placeholderRow` locale formatter. The built-in copy is deliberately position-free ("Loading.") — the grid already announces the position through `aria-rowindex`/`aria-rowcount`, which count in grid coordinates, so restating it in text would read out a second, off-by-one number for the same row — while the formatter context (`NatTableAccessibilityRowPlaceholderContext`, exported from `ng-advanced-table/locale`) still carries the position and total for consumer overrides. A new `natTableRowPlaceholder` content template (directive `NatTableRowPlaceholderTemplate`, context `NatTableRowPlaceholderTemplateContext` with the logical index, the column, and the table) renders inside every placeholder cell; without it the cells stay empty at the fixed row height. Placeholder cells are ordinary roving-tabstop grid cells — arrow, page, and Control/Command + Home/End navigation move through and beyond them — and focus retention works by logical position where no row id exists: a focused placeholder whose window arrives hands focus to the fetched row's cell, and a focused loaded row removed by a window fill keeps focus on the same logical slot.

Window replacement does not reset the scroll. Under remote windowing, swapping `data` and `rowWindowOffset` is the normal fill after the reader deliberately scrolled somewhere, so the row-id append test is bypassed; sorting, filter, and pagination changes, body-state transitions, and a changed `remoteRowCount` still reset to the first logical row.

Development-mode diagnostics warn on non-integer or negative `remoteRowCount`/`rowWindowOffset`, a remote total smaller than the loaded rows, a window offset that pushes the loaded rows past the total, active client-side sorting/filtering/pagination (remote windowing requires the manual modes, because client transformations would operate on the loaded window rather than the dataset), a configured sub-header column (sub-header rows are disabled while `remoteRowCount` is set), and a scroll extent past the cross-engine element-height ceiling — `remoteRowCount × rowHeight` above 16,000,000 CSS pixels, chosen under Gecko's ≈17.9M-px app-unit limit and well under the ≈33.5M-px Blink/WebKit `LayoutUnit` limit shared by Safari 16.5 — naming the effective maximum row count at the configured row height. `natTableExport` additionally warns that export covers only the loaded window under remote windowing; select-all is likewise loaded-scope, and fetching, caching, eviction, and retry stay consumer-owned. One contiguous window is held at a time; jumping replaces it.

Documented in the showcase virtualization topic with a new Remote windowing section, an updated Limitations list, and a live 250,000-row demo whose container fetches the window the reader lands on, plus Playwright pointer and keyboard-accessibility coverage under `e2e/virtualization/`. Virtualization coverage thresholds ratchet up (statements/lines 96 → 97, branches 90 → 91) to lock in the added coverage. Two size ceilings move with this work: `ng-advanced-table` from 71,500 to 74,300 gzipped bytes for the placeholder body-template branch, the plan-builder extent mapping, the new template directive, and the derived remote counts; and `ng-advanced-table/virtualization` from 14,500 to 18,500 for the remote input normalization and diagnostics, the logical-coordinate keyboard/focus handling with window-fill recovery, and the rationale comments ng-packagr preserves in the FESM bundles.
