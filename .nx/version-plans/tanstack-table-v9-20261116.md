**Breaking:** Move to TanStack Table v9 (`@tanstack/angular-table` 9.3). Tables are built with one fixed feature set (filtering, global filter, sorting, pagination, visibility, ordering, pinning, sizing, resizing, row selection), and `ng-advanced-table` exports TanStack's types with that feature set applied, so `ColumnDef<Row>`, `Row<Row>`, `Column<Row>`, `CellContext<Row>`, and the other forwarded types keep their v8 generic shape. Consumer changes: `columnPinning` state uses `start`/`end` instead of `left`/`right` and needs both keys; column definitions use `sortFn` instead of `sortingFn`; `table.getState().<slice>` becomes `table.atoms.<slice>.get()`; `RowSelectionState` is typed `Record<string, true>`; a cell renderer typed with a concrete value (`CellContext<Row, number>`) must take `CellContext<Row, unknown>` and narrow with `getValue<number>()`; the `datetime` sort function compares `Date` subclasses by `getTime()`; and two `undefined` values with `sortUndefined: 'first' | 'last'` now tie instead of being ordered.

Pinned columns now stick with `inset-inline-start`/`inset-inline-end` and the pinned edge shadows mirror in right-to-left tables, so a start-pinned column stays in view in RTL. The package ships a codemod for these changes: `npx -p ng-advanced-table ng-advanced-table-migrate-v9 [--dry-run] src`. The new "TanStack v9 migration" docs topic lists every change and how the codemod handles it.
